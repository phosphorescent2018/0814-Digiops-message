短信管理

本文档是用户与 Agent 围绕短信管理原型进行方案沟通、确认和持续生成的事实依据。只维护当前有效方案，并简短记录会影响当前原型的重要用户决策和变更。

当前方案

  • 原型意图：高精度还原 Digiops 短信管理页面（UAT：messageManage/noteMessage），作为可编辑、可评审的高保真产品原型。
  • 使用场景：产品经理在 Axhub Make 中查看、评审和调整短信管理页的布局、字段、交互与报表展示，作为后续前端开发的需求依据。
  • 当前表达：全局布局（左侧导航 + 顶部栏）+ 三个 Tab（模版 / 发送记录 / 报表），默认激活「发送记录」；数据使用 UAT 真实快照。

补发中心：状态机与数量口径（用户已确认）

批次状态机（六态）

  • 待执行：定时补发已创建，补发时间未到（实际发送数量显示 --）。
  • 执行中：立即补发提交后直接进入；定时补发到点后进入。发送进行中。
  • 已完成：所有应发短信均已完成发送动作（发出了/尝试发出了）。
  • 已终止：人工补发 = 用户主动终止（仅待执行/执行中可终止，需二次确认）；自动补发 = 全局关闭立即中断执行中的批次产生，不提供单批次终止操作。
  • 失败：系统级异常且实际发送数量为 0（启动前失败或执行开始即中断）。
  • 部分失败：系统级异常且实际发送数量 ≥ 1（执行中中断），保留已发送部分统计。
状态触发条件执行完整性可操作
待执行定时补发提交后，未到补发时间未开始终止
执行中立即补发提交后；定时补发到点后进行中终止、详情
已完成所有应发短信完成发送动作100% 处理完详情
已终止人工补发：用户主动终止；自动补发：全局关闭中断部分处理完详情
失败系统异常且实际发送数量为 0（启动前失败或执行开始即中断）未实际发送详情
部分失败系统异常且实际发送数量 ≥ 1（执行中中断）部分处理完详情

「已完成」的定义：只要对每条短信做了发送动作（发出了/尝试发出了），这条就算完成； 批次内所有应发短信都完成发送动作，批次即为「已完成」。 发送状态（成功 / 失败 / 暂无数据）是发送动作之后的结果，属于明细层，不影响批次状态。 批次层看「发没发」，明细层看「发得怎么样」。

数量口径

字段定义展示规则
提交校验数量 提交前用户校验的补发数量（弹窗②「点击校验」结果） 创建批次即有；列头 hover 提示说明
实际发送数量 实际执行了发送动作的条数（执行过程中分批校验通过后累计，含单条提交失败） 待执行显示 --；执行中显示已累计进度；完成 / 终止 / 失败显示最终累计值

执行采用分批滚动「校验 → 发送」：每批校验通过后立即发送该批，再校验下一批； 实际发送数量 = 执行过程中分批校验通过并执行发送动作的累计条数（含单条提交失败）。 相对提交校验数量只可能减少（执行期剔除：退订 / 号码失效 / 重复补发），不可能增加； 新增符合条件的短信不进当前批次，留待下一次补发。

黑名单与执行期差异

  • 人工补发：黑名单在提交前过滤（弹窗①「黑名单用户是否发送」：否=排除，是=含黑名单），由用户选择；执行时不再因黑名单筛人。
  • 自动补发：默认强制校验黑名单，命中黑名单的短信不参与自动补发，不提供「含黑名单发送」选项；自动补发批次详情「黑名单校验」固定展示「是（黑名单内不发送）」。
  • 提交校验数量与实际发送数量的差异，来自提交到执行时间窗口内的变化（号码失效、退订、重复补发等），立即补发通常相等，定时补发可能减少；单条提交失败已计入实际发送数量，不构成差异。

提交后交互（用户确认）

  • 定时/立即补发提交成功后：清空筛选条件、隐藏命中面板，回到初始状态，防止重复提交。
  • 批次列表置顶展示新批次；批次详情（待实现）保存筛选条件快照供追溯。

自动补发技术规格（业务与实现口径）

执行模型

  • 系统常驻定时扫描器，按固定周期运行（建议每 5 分钟一次，参数可配）。
  • 每轮扫描捞起满足触发条件的「待补发」短信，聚合为一个自动补发批次提交；批次状态机与人工补发一致（待执行 / 执行中 / 已完成 / 已终止 / 失败 / 部分失败）。
  • 批次产生策略（规则页可配置，默认值）：达到最大排队数量（默认 1,000 条）立即聚批；未达最大排队数量但该批次首条短信入队已满批次最长等待（默认 15 分钟，起算点为批次首条入队时刻）也聚批；无待补短信则跳过。扫描周期（建议 5 分钟）由后端参数控制，不在规则页暴露。
  • 「补发时间间隔」只约束同一条短信两次自动补发之间的最小间隔，不计算人工补发时间；「最多补发次数」为同一条短信的最多自动补发次数，选择 1 次时「补发时间间隔」置灰不可配置，且该项不再计入必填校验，保存与开启不受影响。
  • 必填项（红色星号）：触发条件（至少 1 个）、最多补发次数、最大排队数量、批次最长等待、生效时段；生效时段默认无选择（不替用户默认全天），用户须显式选择「全天」或「指定时段」；任一必填项未配置时保存与开启均不可用。

触发条件

  • 提交失败时：发送失败（提交即失败，无需等待回执）。
  • 回执判定后：未送达（收到明确回执后触发）；回执超时（24 小时内无明确回执后触发）。
  • 发送状态为「成功 / 暂无数据」的短信进入回执窗口等待；窗口内无明确回执则按回执超时进入补发队列。

开关语义

  • 开关独立展示在页面顶部状态条（标题「自动补发」+ 已开启 / 已关闭标签 + 摘要行 + 右侧开关），不再位于规则卡片内。
  • 规则默认关闭；关闭状态下表单可编辑、可保存。
  • 开启后规则体锁定（不可编辑），保存按钮置灰。
  • 开启 / 关闭均需二次确认弹窗：开启提示「开启后，满足触发条件的失败短信将由系统自动补发，请确认规则已配置正确」；关闭提示「关闭后，系统将立即停止自动补发；已有的自动补发队列会被清空，进行中的人工补发不受影响」。
  • 关闭后系统立即停止自动补发：不再产生新的自动补发批次，已有自动补发队列被清空；执行中的自动补发批次立即中断，批次状态置为「已终止」，保留已发送部分统计；进行中的人工补发（立即 / 定时）不受影响，按原计划执行完毕。

生效范围

  • 本规则为全局默认规则；运营计划若在画布中配置了自动补发组件，以计划配置为准。
  • 2026.8.24 日前的历史短信不参与自动补发。
  • 自动补发默认强制校验黑名单（无用户开关）：命中黑名单的短信自动不补发。

记录口径

  • 自动补发记录采用批次维度，与人工补发记录分开展示（补发中心两个子 Tab 各自独立的记录列表）。
  • 顶部统计展示累计全量、按补发发送记录数统计：补发成功 = 发送成功且已送达；补发失败 = 发送失败，或发送成功但未送达 / 回执超时；待确认 = 其余（回执中、暂无数据）；成功 + 失败 + 待确认 = 累计补发总数（mock：12,846 = 9,214 + 2,536 + 1,096）。状态未终态时数字会随回执变化，实时计算，不存快照。送达状态已无「未知」，暂无数据统一展示为 --。
  • 顶部统计支持按运营计划筛选（可搜索下拉，默认「全部运营计划」）：选择后仅展示该计划的累计补发 / 补发成功 / 补发失败 / 待确认 / 队列中；各计划 mock 数字合计等于全量（5,120 + 4,318 + 3,408 = 12,846，成功 / 失败 / 待确认同口径自洽；队列 5 + 3 + 3 = 11）。「队列中」随所选计划展示该计划当前排队条数，全量视图展示全局队列；顶部状态条摘要保持全局视角。
  • 自动补发记录字段（已确认）：补发批次 ID、当前状态、补发开始时间、补发结束时间、实际发送数量（实际执行了发送动作的条数）、操作（详情）。补发批次 ID 采用前缀区分：人工补发 B 前缀、自动补发 A 前缀。自动补发不提供单批次「终止」操作（止血使用全局关闭开关）。
  • 自动补发批次详情抽屉（仿人工补发）：批次信息（规则来源 / 计划补发时间 / 补发开始·结束时间 / 入队时间 / 黑名单校验，含规则快照）、数量概览（入队数量 = 聚批时进入本批次的短信条数；实际发送数量；执行中显示实时进度）、执行统计（发送 / 送达状态分布，查看发送记录按批次 ID 跳转并自动填入补发批次 ID，导出明细仅终态可用，非终态 hover「待任务结束后可导出」）；底部无终止按钮，已终止批次展示「因关闭自动补发被中断」说明。

运营计划画布技术规格

画布能力

  • 左侧「流程定制」节点面板：进入（客户群组）、动作（判断 / 补发控制 / 结束节点 / 延时器 / A/B测试 / 动作判断 / 群组过滤）、渠道（短信 / WhatsApp / 智能语音 / Viber / Webhook / 切片 / 应用推送 / 电销 / 优惠券）；节点可拖入画布、画布内可拖动、四向端口拖线连接。
  • 网关类节点（判断 / 动作判断 / 群组过滤）最多 2 条出线：第一条出线自动标记「YES（绿✓）」、第二条「NO（红✕）」，超出 2 条弹出红色 toast 拦截。
  • 点击画布节点打开配置面板：判断节点支持事件类型（事件发生 / 业务属性 / 群组人数 / 前置校验）；前置校验含校验项（黑名单校验、发送时段校验）、允许发送时段（最多 3 段、端点相接不冲突、重合时拦截）、非时段固定提示「非允许时段内发送将自动挂起，等到下一允许时段再继续」。补发控制节点含触发条件（提交失败 / 未送达 / 回执超时）、最大补发次数、补发间隔。
  • 画布节点下方仅判断节点展示小字（所选事件类型名：前置校验 / 事件发生 / 业务属性 / 群组人数），其余节点不展示摘要；节点配置数据仍在（双击可编辑），只是画布不显示。
  • 补发控制配置弹窗顶部提示两行：流程将在此停留，直到补发完成（补发成功或达到上限）后继续；补发前复用画布「前置校验」规则，未配置则不校验。提示条与下方「触发条件」间距 20px。

人工补发页技术规格

  • 条件筛选区支持「收起 / 展开」：默认展开 9 个筛选字段，收起后仅保留前 6 个（隐藏路径标记等后 3 个字段），切换按钮位于查询按钮右侧。
  • 查询后命中汇总文案：当前筛选项下命中 X 条，其中黑名单命中 Y 条，任务执行时将重新校验；查询后用户尚未选择黑名单策略，不展示「实际可补」数量；命中为 0 时仅展示「当前条件筛选下无命中」（红色）。
  • 实际可补 actualHit 仅作为内部校验基准（弹窗②「点击校验」返回最新数量 = actualHit × 98%），不在命中汇总中对外展示。
  • 查询按钮防呆（2026-08-14 确认）：默认不选任何筛选项时查询按钮置灰不可点击，hover 提示「请至少选择一项筛选条件」；任意筛选项填写 / 选择后自动恢复可点；点击重置后回到置灰；每两次查询触发一次 0 命中的演示逻辑不受影响。
  • 补发弹窗合并（2026-08-14 确认）：定时 / 立即补发改为单个弹窗完成配置与确认，不再分两步弹窗；弹窗内含补发方式、预计补发时间（定时可编辑、立即执行）、黑名单用户是否发送（单选）、黑名单提示（随选项即时切换）、补发数量（点击校验后原地显示）；底部仅「取消 / 确认补发」，确认前需完成校验且定时时间需晚于当前时间；校验后修改时间或黑名单选项会自动清空校验结果并重新置灰确认键。
  • 弹窗默认不替用户选择（2026-08-14 确认）：黑名单用户是否发送默认不选中（未选择前不展示黑名单提示），定时补发时间默认不填写（显示「请选择补发时间」灰色提示）；两者未完成前「点击校验」与「确认补发」均置灰，hover 校验按钮按缺失项提示「请先选择黑名单用户是否发送」/「请先选择晚于当前时间的补发时间」；填写早于当前时间时输入框标红并提示格式要求。

批次状态机实现

computeStatus(batch):
  if (isTerminated)              → 已终止
  if (isFailed && 实际发送数量 > 0) → 部分失败
  if (isFailed)                  → 失败
  if (定时 && scheduledTime > now) → 待执行
  if (endTime !== '—')            → 已完成
  else                           → 执行中

数量口径实现

命中 hitCount（随机 800~1600；每两次查询第 2/4/6…次返回 0 演示空状态）
  → 黑名单命中 = hitCount × 3.6%
  → 实际可补 actualHit = hitCount − 黑名单命中（仅内部作为弹窗②校验基准，不在命中汇总中展示）
  → 弹窗②校验 verifiedCount = actualHit − 2%（模拟后端校验）
  → 提交校验数量 = verifiedCount
  → 实际发送数量：立即补发 = verifiedCount；定时补发 = null（待执行显示 '—'）
  → 执行开始后按批次滚动累计更新实际发送数量
